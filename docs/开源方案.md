> 基于 2026-10-19 的实际代码核对（`D:\ccgui\douyin_transcribe.py` 1682 行、`douyin_corrector.py` 2427 行、`video_ocr.py` 115 行）。
> 本文回答三个问题：现在怎么跑、要分享给别人缺什么、开源该怎么打包。

> **落地状态（2026-10-19）**：M0–M3 已完成并用真实链接跑通端到端。
> 代码拆成 `cli / config / pipeline / extract / transcribe / ocr / media / browser / ai / render / correct / naming / batch / local / doctor`，

## 0. 结论先行

**做成「一个 CLI 包 + 一个 Agent Skill 外壳」，不要一上来做 exe。**

| 形态 | 定位 | 结论 |
| --- | --- | --- |
| Python CLI 包 | 核心能力，`pipx install` 即用 | ✅ **主体**，先做这个 |
| Agent Skill（SKILL.md） | 给 Claude Code / Codex / DSH 调用的入口 | ✅ 第二层，**薄封装**，调用 CLI，不重复实现 |
| MCP Server | 给任意 Agent 挂工具 | 🔶 可选，CLI 稳定后再加 |
| 桌面 exe / GUI | 给纯小白 | ❌ 首版不建议：torch+whisper 让安装包 2–3 GB，且要处理模型下载 |
| Docker 镜像 | 服务器/批量 | 🔶 可选，镜像约 5 GB |

道理很简单：**Skill 本身不干活**。SKILL.md 只是一段提示词 + 几个脚本入口，浏览器、FFmpeg、Whisper 这些重活仍然需要一个能安装、能升级的 CLI。只发 Skill，用户还是要自己解决 torch、模型、ffmpeg、Chrome。

## 1. 现在是怎么跑的

### 1.1 入口

```bat
run_douyin.bat "https://v.douyin.com/xxxx/"      # 单条
run_douyin.bat "https://v.douyin.com/xxxx/" -v   # 强制视频模式
run_douyin.bat --batch links.txt                 # 批量
```

`run_douyin.bat` 只做三件事：设环境变量 → `uv run --with <11 个依赖>` 起临时环境 → `python -u douyin_transcribe.py`，日志重定向到 `temp_logs/run_时间戳.txt`，最后打印 `===EXITCODE=n===`。

**注意**：真正的主程序不在这个工作区，而在 `D:\ccgui\`；工作区里只有 `.bat`、依赖清单、文档和 385 个产出目录。

### 1.2 解析一条视频会调用哪些工具

| 步骤 | 调用的东西 | 关键参数 / 位置 |
| --- | --- | --- |
| 1 打开页面 | Playwright（chromium，`channel='chrome'`，`headless=False`，持久化 profile） | `douyin_transcribe.py:928` |
| 2 抢焦点处理 | psutil + ctypes 最小化 Chrome 窗口 | `:38 minimize_browser_windows()` |
| 3 抓流地址 | 网络响应拦截 `on_response`，收集音频/视频 URL | `:914` |
| 4 下载 | `requests`/`urllib` 分块写盘，音频 ≥50KB、视频 ≥100KB 才算成功 | `:484 download_to_file()` |
| 5 转码 | FFmpeg → `pcm_s16le / 16kHz / 单声道 WAV`，失败降级「实时录音」 | `:1447` |
| 6 转录 | openai-whisper，`large-v3`、`fp16=False`、`language='zh'`、固定 initial_prompt | `:1460 / :1481` |
| 7 加标点 | AI 接口（MiMo / DeepSeek，OpenAI 兼容），失败回落正则 | `:619 restore_punctuation()` |
| 8 改错字 | 本地字典 2098 条 + 白名单 17 条 | `douyin_corrector.py:15` |
| 9 画面文字 | RapidOCR（onnxruntime），每 1 秒截 1 帧、最多 60 帧、conf>0.5 | `video_ocr.py:11` |
| 10 可靠性分析 | AI 接口，输出 📊/✅/💡/⚠️ 四段、200 字内 | `:645 call_ai_analysis()` |
| 11 归档编号 | 目录按 mtime 重命名为 `{三位数}_{标题}_{YYYYMMDD}` | `:1596 auto_number_folders()` |

图文（note）分支不下载、不做 OCR、不编号，直接 DOM 取文本 → AI 标点 → 字典 → 分析 → `sys.exit(0)`。

### 1.3 产出格式

每条内容一个文件夹：

| 文件 | 内容 | 何时生成 |
| --- | --- | --- |
| `文案.txt` | 纯正文（修订、加标点后） | 总是 |
| `文案_分析版.md` | 标题 + 元信息表 + 正文 + AI 可靠性分析 | 总是 |
| `画面文字.md` | 标题 + 段数 + 原链接 + OCR 编号列表 | 有 OCR 结果时 |
| `修订报告.md` | 统计 + 修正说明表 + 修订后文案 | 有修正时 |
| `info.json` | `url/title/author/duration/content_type/tags/transcript/transcript_raw/ai_reliability_analysis/ocr_texts` | 总是 |
| `audio.wav` / `audio_raw.m4a` | 16k 单声道 / 原始流 | 视频分支 |

`文案_分析版.md` 的固定版式：

```markdown
# {标题}

{标签}

| 项目 | 内容 |
| --- | --- |
| 作者 / 类型 / 时长 / 转录 / 画面文字 / 解析日期 / 原链接 | ... |

---

## 正文
{完整正文，不改字}

---

## AI 可靠性分析
### 📊 基本信息
### ✅ 内容核查
### 💡 使用建议
### ⚠️ 注意事项
```

批量模式额外产出 `batch_summary_{时间戳}.md/.json`（总数/成功/失败/每条耗时）。

## 2. 开源成熟度盘点

**已有的好东西**（这些是项目的真价值）：

- 完整可用的链路：抓流 → 下载 → 转码 → 转录 → 标点 → 改错 → OCR → 分析 → 归档，每一环都有降级
- 2098 条 ASR 修正字典（中文短视频口误/专有名词），同类项目里很少见
- 四段式「可靠性分析」prompt，比裸转录多一层信息
- 环境变量驱动的开关（模型、OCR、供应商、输出目录）已经比较规整
- 一份 500 行的真实工作流文档

**缺的（开源前必须补）**：

| 问题 | 现状 | 影响 |
| --- | --- | --- |
| 密钥明文 | `config.ini` 里有 `tp-...` 的 MiMo key | 一旦提交就是事故 |
| 个人环境 | 3 处硬编码（输出目录、cookie profile、ffmpeg 绝对路径） | 别人跑不起来 |
| 单体脚本 | 1682 行顶层代码，`sys.exit()` 散落，没有 `main()` | 没法测试、没法复用 |
| Windows 绑定 | `channel='chrome'`、psutil 最小化、powershell 读注册表取 key、GBK 修复 | macOS/Linux 直接崩 |
| 无打包 | 没有 `pyproject.toml`，靠 `uv --with` 现拉 | 装不上、升不了级 |
| 无测试 | 0 个测试 | 改一行不知道坏没坏 |
| 无许可证 | 没有 LICENSE | 别人不敢用 |
| 个人工作流耦合 | 自动编号 382 个目录、日期命名 | 别人不需要，甚至危险 |

## 4. 必改清单（P0 → P1）

### P0（这些不修完，别推 GitHub）

1. **洗密钥**：删 `config.ini` 里的 key，改 `.env.example`；删 `*.bak-*` 备份文件（里面可能也有 key）；`git init` 前先跑一遍 `grep -ri "tp-\|sk-\|api_key"`。
2. **洗个人数据**：`D:\ccgui\data\cookies\douyin_profile`、385 个产出目录、`temp_logs/`、`temp_audio.wav` 全部进 `.gitignore`；示例只放 1–2 条自己原创内容的产出。
3. **路径可配**：`:30/:31/:32` 三处硬编码 → `config.py`（默认 `./output`、`~/.cache/douyin-parse/browser`、`shutil.which('ffmpeg')` 兜底 `imageio_ffmpeg`）。
4. **加 `main()`**：把 1682 行顶层流程包进函数，`sys.exit()` 换成异常 + 退出码；这是所有测试和 CLI 的前提。
5. **许可证 + 免责声明**：代码 MIT；README 里写清「仅供个人学习研究，产出文案版权归原作者，请勿再分发」。

### P1（决定别人用不用得下去）

6. **跨平台**：`channel` 默认 `chromium`（`playwright install chromium`）+ `--browser chrome` 兜底；psutil 最小化只在 Windows 生效；删掉 powershell 读注册表的 key 探测，改成「只读 env / 配置文件」。
7. **换转录后端**：默认 `small`，并支持 `faster-whisper`（CTranslate2，CPU 上快 3–4 倍，不用装 torch，安装体积从 ~2.5 GB 降到 ~300 MB）。`large-v3` 改成显式 `--model large-v3`。
8. **AI 可选且默认关闭**：`--ai none` 全本地跑通（正则标点 + 跳过分析），`--ai deepseek` 才联网。
9. **解耦个人工作流**：自动编号改成 `--auto-number`，日期后缀改成 `--name-template`。
10. **支持本地文件**：`douyin transcribe ./a.mp4`。这样工具不依赖抖音也能用，测试也才有了稳定输入。
11. **`doctor` 子命令**：检查 Chrome/Chromium、ffmpeg、模型缓存、API key、磁盘空间，一次把环境问题说清楚。

## 5. CLI 设计

```bash
douyin parse  <url|share-text> [--out DIR] [--model small] [--no-ocr] [--ai none|deepseek|mimo]
                               [--force-video] [--keep-media] [--format md,json,txt]
```

## 7. Skill 怎么包（第二层）

```markdown
---
name: douyin-parse
description: 解析抖音分享链接，提取文案、画面文字与可靠性分析。Use when the user pastes a douyin.com / v.douyin.com link, or asks to 提取抖音文案/视频转文字/批量解析。
---

# 抖音文案解析

## 前置
运行 douyin doctor，确认 ffmpeg 与浏览器就绪；未安装则先 douyin config --init。

## 用法
douyin parse "<链接>" --out ./output --ai none
批量：douyin batch links.txt

## 输出
output/{id}_{title}/ 下生成 文案.txt、文案_分析版.md、画面文字.md、info.json。
向用户汇报时贴 文案_分析版.md 的正文与「AI 可靠性分析」，不要贴运行日志。
```

要点：**SKILL.md 里只写「什么时候用、怎么调、怎么汇报」，不复制实现**；安装脚本负责 `pipx install`。这样一个 skill 可以同时给 Claude Code、Codex、DSH 用。

## 9. 合规与风险（必须写进 README）

1. **抖音用户协议**：抓流属于非官方接口，可能违反平台条款，且随时会失效。项目应定位为「个人学习/自用备份」，默认不提供高频批量、不内置绕过风控的手段。
2. **著作权**：`文案.txt`、`info.json` 的正文版权归原作者，**仓库里不要放抓取来的语料**；示例用自己拍的内容。
3. **AI 供应商条款**：MiMo/DeepSeek 的 key 与内容政策，README 里说明「可选、默认关闭」。
4. **脆弱性**：依赖抖音前端结构与接口，一次改版就可能全挂。README 顶部写「本项目会随平台改版失效，请先跑 `doctor`」，并留 issue 模板收「失效报告」。

## 10. 决定 star 数的三个差异点

1. **ASR 后处理词典**：2098 条中文短视频纠错（`Cloud→Claude`、`chatgbt→ChatGPT`、`GEU→GEO`），可独立成 `asr-corrector` 子包，别人能拿去配自己的转录流程。建议拆 `base.json` + `domains/*.json`，支持用户自定义词典。
2. **可靠性分析**：四段式（基本信息/内容核查/使用建议/注意事项），比裸转录多一层，是「内容研究」场景的刚需。
3. **全本地可跑**：`--ai none` + `small` 模型，不联网、不花钱也能出文案——这是最低门槛的体验。

> 顺手记两个数据质量问题（样例 001 实测）：`修订报告.md` 里出现过 `| token | token | 1 |` 这种「改了等于没改」的条目；同一条内容 `info.json` 的 `transcript` 是 5282 字，而 `文案_分析版.md` 标「转录 5265 字」，两处字数算法不一致。开源前统一口径，不然会被当成 bug 提 issue。
