# 抖音视频解析工作流程

## 概述

本文档说明从接收抖音视频链接到在聊天窗口输出最终结果的完整工作流程。

**文档基准**：与 `D:\ccgui\douyin_transcribe.py`（2026-10-19 修订版）、`douyin_corrector.py`（2026-10-16 版）、`video_ocr.py` 的实际代码逐条核对过。

> 2026-10-19 同时做了两处代码修复：Whisper 模型改为 `large-v3`（可环境变量覆盖）、自动编号加排除名单。详见第八节与第十三节更新日志。

---

## 一、整体流程图

```
用户分享抖音链接
       ↓
   识别链接，直接执行（不反复确认）
       ↓
   调用解析脚本（python -u，加 -u 禁用缓冲）
       ↓
  Playwright 打开页面 → new_page() 后立即最小化浏览器
       ↓
  拦截网络响应，收集音频流 / 视频流 URL
       ↓
  ┌──────────────┴──────────────┐
  │ 判定图文                     │ 判定视频
  ↓                              ↓
 DOM 直读文本              下载音频流/视频流
  ↓                              ↓
  │                      FFmpeg 转 16kHz 单声道 WAV
  │                       （失败则降级为实时录音）
  │                              ↓
  │                      Whisper(large-v3) 语音转录
  │                              ↓
  │                      AI 标点恢复 + 分段
  │                              ↓
  │                      RapidOCR 视频画面文字提取
  └──────────────┬───────────────┘
                 ↓
        douyin_corrector 字典修订
                 ↓
        AI 可靠性分析（MiMo / DeepSeek）
                 ↓
        保存 文案.txt + 画面文字.md + 文案_分析版.md + 修订报告.md + info.json
                 ↓
        自动编号所有文件夹（仅视频分支会触发）
                 ↓
        聊天窗口输出完整文案 + AI 分析
```

## 二、聊天窗口输出格式

**只展示以下内容，不展示修订对照表、OCR 原文、运行日志：**

```
## ✅ 解析完成

**视频**：{标题}（{博主名}）
**时长**：{时长} | **转录**：{字数}字 | **OCR**：{段数}段 | **耗时**：{秒数}秒

---

{完整的格式化文案正文，包含 AI 补好的标点与分段}

---

## AI 可靠性分析

{直接粘贴脚本生成的 AI 分析内容}
```

脚本生成的 AI 分析固定为四段 emoji 结构（总字数约 200 字以内）：

```
📊 基本信息     类型 / 时长 / 转录字数
✅ 内容核查     事实性评估 / 可能的偏差 / 来源可信度（高·中·低）
💡 使用建议     如何引用这些信息 / 是否需核实原始来源
⚠️ 注意事项     误导性内容 / 建议交叉验证的关键点
```

**输出原则**：
- ✅ 博主信息（标题、作者）
- ✅ **完整的格式化文案正文**（不是摘要或结构概览）
- ✅ AI 可靠性分析（原样贴出，不要自己再编一份）
- ✅ `文案_分析版.md` 现为 Markdown 版式（标题 + 元信息表 + 正文 + AI 分析），可直接复制粘贴
- ❌ 不展示 ASR 修订对照表（在 `修订报告.md` 里，不进聊天窗口）
- ❌ 不展示 OCR 提取的原始文字列表
- ❌ 不展示脚本运行日志
- ❌ 不展示"文案结构"摘要（要贴完整正文）

**若 AI 未启用**：脚本会在分析版里写 `⚠️ AI 分析暂时不可用（API 未配置或调用失败）`，此时聊天窗口照实说明分析缺失，不要伪造分析。

## 三、详细步骤

### 步骤1：识别链接并直接执行

用户分享抖音链接后，**直接调用脚本，不需要反复确认**。

**识别规则**：

| 特征 | 说明 |
|------|------|
| 链接格式 | `https://v.douyin.com/xxxxxx/` 或含 `douyin.com` |
| 分享格式 | 包含数字+符号+链接（如 `7.12 :7pm 05/17 nda:/`） |
| 关键词 | `抖音`、`Dou音`、`复制此链接` |

---

### 步骤2：调用解析脚本

**脚本位置**：`D:\ccgui\douyin_transcribe.py`

**单条链接**（⚠️ 必须加 `-u` 禁用输出缓冲）：
```bat
cd D:\ccgui && uv run --with playwright --with openai-whisper --with numpy --with scipy --with soundfile --with requests --with rapidocr-onnxruntime --with psutil --with sounddevice --with imageio_ffmpeg python -u douyin_transcribe.py "抖音链接" > D:\ccgui\output_latest.txt 2>&1
```

**强制视频模式**（当视频被误判为图文时，简写 `-v` 等效）：
```bat
cd D:\ccgui && uv run --with playwright --with openai-whisper --with numpy --with scipy --with soundfile --with requests --with rapidocr-onnxruntime --with psutil --with sounddevice --with imageio_ffmpeg python -u douyin_transcribe.py "抖音链接" --force-video > D:\ccgui\output_latest.txt 2>&1
```

> `--with sounddevice --with imageio_ffmpeg` 是为「录音降级方案」和「FFmpeg 自动定位」准备的。若已有稳定的本地环境（如 `D:\ccgui\requirements.txt`），也可直接用该环境跑，不必走 `uv --with`。

**脚本实际执行顺序**：

1. `ensure_runtime_ready()` 检查输出目录和 FFmpeg，并打印当前 AI Provider
2. 步骤1：Playwright 打开页面 → `new_page()` 后**立即最小化浏览器** → 拦截响应收集流地址 → 判定图文/视频 → 提取标题、作者、标签
3. **图文分支**：从 DOM 直读文本 → AI 标点恢复 → 字典修订 → AI 分析 → 保存 → `sys.exit(0)`（**不下载、不 OCR、不触发文件夹编号**）
4. **视频分支**
   - 步骤2：优先下载纯音频流（≥50KB）→ 再下载视频流（≥100KB）→ 检查视频是否自带音频
   - 步骤3：FFmpeg 提取音频（`pcm_s16le / 16kHz / 单声道`）。方案A 音频流转 WAV → 方案B 视频抽音 → 方案B2 换其他视频 URL 重试 → **方案C 实时录音降级**
   - 步骤4：Whisper 转录（见第五节）
   - AI 标点恢复 + 分段（失败自动降级为正则方案）
   - 步骤5.5：RapidOCR 提取画面文字（见第六节）
   - 步骤6：AI 可靠性分析
   - 保存 `文案.txt`（纯正文）、`画面文字.md`（OCR 单独存放，仅当有 OCR 结果时）、`修订报告.md`（仅当有修正）、`info.json`、`文案_分析版.md`
   - 删除中间文件 `video.mp4`
   - 步骤7：`auto_number_folders()` 自动编号所有文件夹

> **方案C 录音降级**：脚本会重新打开浏览器、把视频静音重置后从头播放，同时用 `sounddevice` 录制系统默认输入设备（48kHz 双声道），录制时长 = `min(视频时长+3, 900)` 秒，然后再转 16kHz。这是一条**需要真实播放完整个视频**的慢路径，且依赖系统有可用录音设备，仅在下载全部失败时触发。

---

### 步骤3：AI 优化文案

**注意：此步骤已由脚本自动完成，不再需要人工逐篇改。**

脚本内置两次 AI 调用：

| 环节 | 函数 | 作用 | 参数 |
|------|------|------|------|
| 标点恢复 | `restore_punctuation()` → `call_ai()` | 给无标点文案加标点、按 2–4 句分段，不改文字 | temperature 0.1，max_tokens 8000 |
| 可靠性分析 | `call_ai_analysis()` | 生成 📊/✅/💡/⚠️ 四段分析，200 字内 | temperature 0.3，max_tokens 2000 |

任一环节失败都会降级（标点走正则、分析写"暂时不可用"），不会中断流程。

**仍需人工/助手在聊天窗口做的事**：
1. 按第二节格式贴出**完整正文**，不要只给摘要
2. 检查 AI 标点恢复是否出现误断句，必要时微调
3. 发现新的 ASR 错误时，追加到 `douyin_corrector.py` 的 `CORRECTIONS` 字典（见第七节）

---

### 步骤4：聊天窗口输出

按"第二节：聊天窗口输出格式"输出最终结果。**必须贴完整文案正文**，不是结构摘要。

## 四、视频内容检测

**检测逻辑**（`douyin_transcribe.py` 步骤1）：

| 检测项 | 权重 | 说明 |
|--------|------|------|
| URL 包含 `/note/` | +2 | 图文强信号 |
| 无 `<video>` 元素 | +1 | 图文特征 |
| 大图（>100px）>3 且无播放器 | +1 | 图文特征 |
| 图文 DOM 结构 | +1 | `image-note`/`slide`/`swiper`/`carousel`/`gallery-view`/`image-viewer` |
| 标题关键词 | +1 | `#图文` `#图片` `#笔记` `#图集` `#相册` `【图文】` |

**判定规则（注意与旧版不同）**：

- 若**存在 `<video>` 元素或 URL 含 `/video/`**：`is_image_text = ('/note/' in URL) or (score >= 3)`
- 否则：`is_image_text = score >= 2`

即：**有播放器的页面阈值实际提高到 3 分**，避免纯视频被误判为图文。

**误判处理**：加 `--force-video`（或 `-v`）强制走视频流程。

**失败兜底**：若始终没加载到内容页（`/video/`、`/note/`、`modal_id` 都不在 URL 里），脚本会截图存为 `{OUTPUT_BASE}/debug_{时间戳}.png` 并以退出码 1 结束。

## 五、Whisper 语音转录

**实际配置**：

| 项目 | 实际值 |
|------|--------|
| 模型 | `large-v3`（`WHISPER_MODEL = os.environ.get('DOUYIN_WHISPER_MODEL', 'large-v3')`） |
| 推理精度 | `fp16=False`（CPU） |
| 语言 | `language='zh'` |
| 线程 | torch 默认使用全部核心（本机 24 线程） |
| initial_prompt | 固定为"以下是普通话短视频内容，可能涉及财税、自媒体、AI工具、经营合规…请准确保留专有名词、人名、平台名和数字。" |

**切换模型**：临时降级不用改代码，设环境变量即可，例如
```bat
set DOUYIN_WHISPER_MODEL=small
```
可选值：`small`(461MB) / `medium`(1.46GB) / `large-v3`(2.94GB)。**三者权重均已在本地缓存** `~/.cache/whisper`，切换不触发下载。

**已验证**：`large-v3` 在本机加载耗时 **12.8 秒**（i9-14900HX，31.8GB 内存），加载本身不是瓶颈。

> **历史说明**：2026-10-12 版代码实际用的是 `small`，与当时文档写的 `large-v3` 不符，已在 2026-10-19 修正为 `large-v3`。另外 2026-10-08 ~ 10-12 期间补跑用的是一次性脚本 `run_transcribe_*.py`，那些脚本用的是 `base` 模型（只对旧音频重跑，不做下载）。

**耗时参考**：

`small` 模型的整机实测（含下载/OCR/AI 全流程）：

| 样本 | 总耗时 |
|------|--------|
| `output_try_20260921_rerun.txt` | 57.5 秒 |
| `output.txt` | 79.0 秒 |
| `output_latest_2.txt` | 295.5 秒 |

`large-v3` 模型的实测（2026-10-19，30 分钟视频）：

| 指标 | 实测值 |
|------|--------|
| 音频时长 | 1795 秒（29分55秒） |
| 转录帧数 | 179,467 帧 |
| 处理速度 | 约 **60 frames/s** |
| 转录耗时 | 约 **50 分钟** |
| 与音频时长比 | 约 **1.7 倍** |

⚠️ **结论：`large-v3` 在 CPU 上跑长视频非常慢。** 短视频（1-3 分钟）可以接受；**10 分钟以上的视频建议用 `DOUYIN_WHISPER_MODEL=small`**，或者接受后台跑。

## 六、视频画面文字提取（OCR）

**工具**：RapidOCR（`rapidocr-onnxruntime`，ONNX Runtime）

**实际参数**（`video_ocr.py`）：

| 项目 | 实际值 |
|------|--------|
| 截帧间隔 | 1.0 秒 |
| 最大截帧数 | 60 帧（长视频只取前 60 秒的画面，**不是全片抽帧**） |
| 置信度阈值 | `conf > 0.5` |
| 最短文字长度 | ≥ 2 字 |
| 去重方式 | **精确字符串去重**（`text not in seen_texts`），不是模糊匹配 |

**关闭方式**：设环境变量 `DISABLE_VIDEO_OCR=1` 可整段跳过 OCR。

> 旧文档写的"Levenshtein 距离 < 0.3 视为重复"与代码不符，已修正。

**输出位置**：OCR 结果**单独存为 `画面文字.md`**（标题 + 段数 + 原链接 + 编号列表），同时明文存放在 `info.json` 的 `ocr_texts` 字段。`文案.txt` 只保留纯正文，不再混入 OCR（2026-10-19 起）。

**适用场景**：
- ASR 识别不出的人名/地名/品牌名
- 视频画面上的数据/图表文字
- 评论区/弹幕截图中的文字（注意 60 帧上限）

## 八、文件夹自动编号

**触发时机**：**仅视频分支**在脚本结尾自动执行。图文分支在保存后直接 `sys.exit(0)`，不会触发编号。

**编号逻辑**：
1. 扫描 `OUTPUT_BASE` 下所有目录，**排除以 `__tmp` 开头的**
2. 已有编号时先做数量校验，数量一致就整体跳过（避免每次白跑一遍重命名）
3. 需要重编号时：先全部改名为 `__tmp001__` ~ `__tmpN__`（避免重名冲突）
4. 再按 mtime 升序改为 `001_xxx` ~ `NNN_xxx`，已有编号前缀先用 `^\d{3}_` 剥掉再重加
5. 顺带清理残留的 `__tmp*__` 目录，**但只删空目录**；非空的一律跳过并告警，防止把重命名中断留下的真实内容当垃圾删掉

**编号格式**：`{三位数}_{标题}_{日期}`（如 `077_第4课_Claude Code提效指南_20260630`）

**目录名来源**：`{safe_name(title)}_{YYYYMMDD}`，其中 `safe_name()` 会把 `\ / : * ? " < > | # \n \r` 替换为 `_`，并截断到 40 字符。

**当前规模**：截至 2026-10-19，`D:\ccgui项目文件\CC抖音解析\` 下已编号到 **382**。

> ✅ **已修复（2026-10-19）**：已加排除名单 `NUMBER_EXCLUDE_PATTERNS`，把 `__pycache__`、`temp_*`、`temp-*`、`batch_summary_*`、`debug_*`、`.隐藏目录`、`__tmp*` 全部排除在编号之外；同时会**自动剥掉这些目录身上已有的编号前缀**（否则会出现重复号）。剔除后会强制做一次连续重编号，补上空号。
>
> 现存的两个历史遗留 `025___pycache__`、`026_temp_video` 会在**下一次视频任务运行结束时自动改名**为 `__pycache__`、`temp_video` 并让编号重新连续，无需手动处理。

## 十一、批量模式与环境变量

### 批量模式

```bat
cd D:\ccgui && uv run --with ... python -u douyin_transcribe.py --batch links.txt
```

- `links.txt`：一行一个链接，**空行和 `#` 开头的行自动跳过**（UTF-8 BOM 兼容）
- 逐条以子进程方式调用本脚本，**单条失败不影响整批**
- 结束时在 `OUTPUT_BASE` 写 `batch_summary_{时间戳}.md` 和 `.json`，含总数/成功/失败/每条耗时/输出目录或错误摘要
- 全部成功返回 0，有失败返回 1

### 环境变量

| 变量 | 作用 | 默认 |
|------|------|------|
| `DOUYIN_OUTPUT_BASE` | 覆盖输出根目录 | `D:/ccgui项目文件/CC抖音解析` |
| `DISABLE_VIDEO_OCR` | 设为 `1` 跳过 OCR | 不跳过 |
| `DOUYIN_WHISPER_MODEL` | Whisper 模型规格（`small`/`medium`/`large-v3`） | `large-v3` |
| `DOUYIN_AI_PROVIDER` | 强制选择 AI 供应商：`mimo` 或 `deepseek` | 不设则按 MiMo → DeepSeek 顺序自动探测 |
| `AI_PROVIDER` | 显式指定 provider | 自动探测 |
| `AI_API_URL` | AI 接口地址 | MiMo 或 DeepSeek |
| `AI_API_KEY` | AI 密钥（设了就完全绕过探测，优先级最高） | 从系统环境变量探测 |
| `AI_MODEL` | 模型名 | `mimo-v2.6-flash` / `deepseek-chat` |
| `AI_API_FORMAT` | `anthropic` 或 `openai` | `openai` |

**AI 探测顺序**：
1. 若环境变量已给 `AI_API_KEY` + `AI_API_URL`，直接用（优先级最高）
2. **快速通道（2026-10-19 新增）**：直接从当前进程环境变量按顺序找，命中即用
   | 顺序 | 环境变量 | 判定 | 接口地址 | 默认模型 |
   |---|---|---|---|---|
   | 1 | `XIAOMI_MIMO_API_KEY` | MiMo | `token-plan-cn.xiaomimimo.com` | `mimo-v2.6-flash` |
   | 2 | `ANTHROPIC_AUTH_TOKEN`（须 `tp-` 开头） | MiMo | `token-plan-cn.xiaomimimo.com` | `mimo-v2.6-flash` |
   | 3 | `DEEPSEEK_API_KEY` | DeepSeek | `api.deepseek.com` | `deepseek-chat` |
3. 快速通道没命中时，才逐作用域（Process/User/Machine）调 `powershell` 读注册表探测
4. 都没有 → `AI_ENABLED = False`，流程继续但标点走正则、分析写"暂时不可用"

**切换供应商**（一行，不改代码）：
```bat
set DOUYIN_AI_PROVIDER=deepseek
```

> **为什么要加快速通道**：本机 `powershell` 首次启动需要约 **53 秒**，而探测用的 `timeout` 只有 5 秒，导致探测**100% 超时被 `except` 静默吞掉**，于是明明配了 key 也永远显示"未启用"。现在走 `os.environ`，耗时 0.00 秒、不 spawn 任何子进程。（`timeout` 也已放宽到 60 秒兜底）

**已实测可用**（2026-10-19，均用 Python `requests` 按脚本真实请求形状验证）：

| 供应商 | 模型 | 延迟 | 输出 |
|---|---|---|---|
| MiMo（cn） | `mimo-v2.6-flash` | 10.9 秒 | 330 字，四段 emoji 结构完整 |
| MiMo（cn） | `mimo-v2.6-pro` | 9.7 秒 | 245 字 |
| DeepSeek | `deepseek-chat` | 1.4 秒 | 190 字 |

> **注意端点**：MiMo 必须用 **`token-plan-cn.xiaomimimo.com`**。脚本早期硬编码的是 `token-plan-sgp.xiaomimimo.com`，对现有 key 返回 **401 未授权**，已于 2026-10-19 修正。

## 十二、已知问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 视频被误判为图文 | 判定阈值逻辑 | 加 `--force-video`（或 `-v`） |
| 脚本输出为空/超时 | Python 输出缓冲 | 必须加 `-u` 标志 |
| `subprocess.run` 报 GBK 编码错误 | Windows 默认 GBK | 所有 `subprocess` 调用已带 `encoding='utf-8', errors='replace'` |
| `__tmp*__` 文件夹残留 | 上次运行中断 | `auto_number_folders()` 开头自动清理 |
| `check_result.stderr` 为 None | FFmpeg 输出含特殊字符 | 已用 `(check_result.stderr or '')` 防空 |
| 浏览器窗口抢焦点 | Playwright 打开浏览器 | `new_page()` 后立即 `minimize_browser_windows()` |
| Whisper 转录无标点 | Whisper 输出特性 | AI 标点恢复，失败降级正则 |
| **AI 分析静默失效** | ✅ **已修复（2026-10-19）**：根因是本机 `powershell` 启动需约 53 秒，而探测用的 `timeout=5` 必然超时，异常被 `except` 吞掉，导致配了 key 也永远报"未启用" | 已加 `os.environ` 快速通道（0.00 秒、0 子进程），并把 `timeout` 放宽到 60 秒。运行开头看 `AI分析: 启用 (Provider: …)` 这行确认 |
| **换 large-v3 后转录变慢** | CPU 跑 2.94GB 模型 | 慢到影响使用就设 `DOUYIN_WHISPER_MODEL=small` 回退，无需改代码 |
| **下载全失败时会很慢** | 走方案C 实时录音，需真实播完整条视频 | 观察日志是否出现"所有下载方案失败，改用录音方案" |
| OCR 只覆盖前 60 秒 | `max_frames=60` + 每秒 1 帧 | 长视频的画面文字会漏，如需全片需调大 `max_frames` |
| 图文分支不触发编号 | 图文在 `sys.exit(0)` 提前结束 | 如需编号，手动跑一次视频任务或单独执行编号 |
