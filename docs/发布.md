# 发布到 PyPI

本项目用 **Trusted Publishing（OIDC）**，不存任何 API token。

## 一次性配置（在 PyPI 网页上做，约 2 分钟）

1. 登录 <https://pypi.org>（没有账号先注册并验证邮箱）
2. 打开 <https://pypi.org/manage/account/publishing/>
3. 在 “Add a new pending publisher” 里填：

| 字段 | 值 |
| --- | --- |
| PyPI Project Name | `douyin-parse` |
| Owner | `panghulo1994` |
| Repository name | `douyin-parse` |
| Workflow name | `publish.yml` |
| Environment name | `pypi` |

4. 保存。之后 GitHub 上发布 Release 时，`publish.yml` 会用 OIDC 直接上传。

> 仓库里已经有 `environment: pypi` 和 `id-token: write`，不需要再建 token 或 secret。
> 如果以后改了仓库名 / 工作流文件名 / environment 名，PyPI 那边的配置要同步改。

> **发布方式二选一**：推 `v*` 标签，或者发布 GitHub Release。
> 两个都做会触发两次发布，第二次因为「该版本已存在于 PyPI」而失败。
> 推荐只推标签：`git push origin v0.1.2`。

## 发一个版本

```bash
# 1. 改版本号（两处）
#    pyproject.toml: version = "0.1.1"
#    CHANGELOG.md:   加一节
git add -A && git commit -m "chore: release v0.1.1"
git tag -a v0.1.1 -m "v0.1.1"
git push origin main --tags
```

2. 在 GitHub 上 **Releases → Draft a new release**，选 `v0.1.1`，写说明，**Publish release**
3. Actions 里的 “Publish to PyPI” 会自动跑：构建 → `twine check` → 上传
4. 成功后检查 <https://pypi.org/project/douyin-parse/>

## 本地先验证一遍

```bash
python -m pip install build twine
python -m build
python -m twine check dist/*
```

产物在 `dist/`：`douyin_parse-0.1.0-py3-none-any.whl` 和 `.tar.gz`。

## 常见失败

| 报错 | 原因 |
| --- | --- |
| `Invalid or non-existent authentication information` | PyPI 的 pending publisher 字段和仓库对不上 |
| `File already exists` | 版本号没改，PyPI 不允许覆盖同版本 |
| `Trusted publishing exchange failure` | Actions 里没给 `id-token: write`，或 environment 名不是 `pypi` |
